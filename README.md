# voice2price — голосовые заказы в список позиций

Голосовое сообщение клиента («Мустафино, Лениногорск. Бочок индейки килограмм, дальше краковская три…»)
превращается в черновик заказа: клиент из справочника филиала, позиции номенклатуры, количества
и единицы. Строка, в которой есть сомнение, уходит менеджеру на проверку с понятной причиной.

План и отложенные идеи — [PLAN.md](PLAN.md). Как измерено качество разбора —
[experiments/voice-order-20260924/README.md](experiments/voice-order-20260924/README.md).

## Запуск

```bash
docker compose up -d --build
```

- Интерфейс: http://localhost:3000
- API бэкенда: http://localhost:5000/api/…

`--build` нужен после каждого изменения кода бэкенда: код копируется в образ, тома с исходниками
у бэкенда нет. Фронтенд подхватывает изменения в `src/` сам (Vite).
Схема БД создаётся и дополняется при старте бэкенда (`backend/init_db_entrypoint.sh` → `models_db.init_db`).

## Как пользоваться

1. **Филиалы** — создать филиал, импортировать из 1С номенклатуру и клиентов (XLSX). После импорта
   показывается проверка справочника: позиции, которые голосом не различить.
2. **Загрузка файлов** — выбрать филиал, способ распознавания (GigaAM локально или SpeechKit)
   и загрузить голосовые сообщения.
3. **Результаты** — расшифровка, клиент, позиции заказа; спорные строки подсвечены с причиной.
4. **Яндекс Облако** — нужно только для SpeechKit и разбора через YandexGPT: API-ключ сервисного
   аккаунта, Folder ID, бакет Object Storage и статический ключ доступа к нему.
5. **XLSX импорт** — посмотреть структуру файла 1С до импорта.

## Устройство

| Сервис | Что делает |
|---|---|
| `frontend` | React + Vite, порт 3000; все запросы идут через прокси `/api` |
| `backend` | Flask, порт 5000: распознавание, разбор заказа, справочники филиалов |
| `gigaam` | локальное распознавание речи GigaAM-v3 ([services/gigaam](services/gigaam/README.md)) |
| `postgres` | все данные: филиалы, номенклатура, клиенты, словарь произношений, настройки |
| `redis` | кэш словаря произношений и очередь задач GigaAM; без кэша всё читается из БД |

Бэкенд подробно — [backend/README.md](backend/README.md).

## Требования к интерфейсу

Все подписи, введённые тексты и плейсхолдеры должны быть контрастны фону во всех состояниях
(обычное, фокус, ошибка, disabled). Правила: [UI_CONTRAST_REQUIREMENTS.md](UI_CONTRAST_REQUIREMENTS.md).

## Решение проблем

- **Изменения бэкенда не видны** — `docker compose up -d --build backend`.
- **Интерфейс не видит бэкенд** — `curl http://localhost:5000/api/health`, затем `docker compose logs backend`.
- **«relation does not exist»** — бэкенд стартовал раньше базы; `docker compose restart backend`.
- **Порт занят** — поменять внешний порт в `docker-compose.yml`, для фронтенда — и `VITE_BACKEND_URL` в `.env`.
