# Требования к контрастности UI (обязательно для всех элементов)

## Критическое правило

**ВСЕ подписи, введенные тексты, плейсхолдеры, значения полей, сообщения об ошибках/успехе, иконки и кнопки ДОЛЖНЫ проверяться на контрастность с фоновым цветом — как в исходном (неизмененном) состоянии, так и после любого изменения (валидация, disabled, focus, заполненное поле).**

Черный или темно-серый текст на темном фоне и белый/светло-серый текст на светлом фоне — **критический дефект**, блокирующий работу с интерфейсом. Такие правки не принимаются.

## Стандарт WCAG AA (минимум)

| Тип текста | Минимальный контраст |
|---|---|
| Обычный текст (≤18px) | 4.5:1 |
| Крупный текст (≥18px bold / ≥24px) | 3:1 |
| Иконки, границы полей, статусные элементы | 3:1 |

## Правила для проекта (Tailwind)

1. **Светлые фоны** (`bg-white`, `bg-gray-50`, `bg-blue-50`, `bg-red-50`, `bg-green-50`):
   - Основной текст: `text-gray-900`
   - Вторичный текст / подсказки: `text-gray-600` (не светлее!)
   - Плейсхолдеры: `placeholder-gray-500` (не `placeholder-gray-300/400`)
   - Ошибки: `text-red-700`; успех: `text-green-700`

2. **Темные фоны** (`bg-gray-700/800/900`, `bg-black`, цветные `bg-blue-600`, `bg-red-600` и т.п.):
   - Текст: только `text-white` или `text-gray-100/200`
   - **Запрещено:** `text-gray-900`, `text-black`, `text-gray-700` на темном фоне

3. **Поля ввода**: цвет текста явно задается через `text-gray-900` + `bg-white`. Нельзя оставлять текст «по умолчанию», если у контейнера может быть темный фон.

4. **Disabled-состояния**: контраст не ниже 4.5:1 (например, `bg-gray-200` + `text-gray-700`, а не `bg-gray-100` + `text-gray-400`).

5. **Состояния валидации** (рамка/фон меняются при вводе): читаемость проверяется в КАЖДОМ состоянии отдельно:
   - пустое, заполненное, ошибка (`bg-red-50`), успешно (`bg-green-50`), focus.

## Чек-лист перед коммитом UI-изменений

- [ ] Каждый новый/измененный элемент просмотрен на ФАКТИЧЕСКОМ фоне приложения.
- [ ] Проверены все состояния: до изменения значения, после изменения, ошибка, успех, disabled.
- [ ] Подписи label видны на фоне карточки/вкладки.
- [ ] Введенный пользователем текст виден во всех состояниях поля.
- [ ] Иконки внутри label/кнопок контрастны (не `text-gray-300/400` на белом).

## История инцидентов (почему это критично)

- Подпись **«API_KEY — API-ключ сервисного аккаунта SpeechKit *»** была плохо видна (нарушение контраста label/фона) — исправлять немедленно при обнаружении.
- Поле неизмененного ID сервисного аккаунта рендерилось черным текстом до первого изменения — недопустимо: состояние «до изменения» обязано быть читаемым.

Данные требования распространяются на все компоненты: `YandexCloudSettings.tsx`, `AudioAnalyzer.tsx`, `FileUploader.tsx`, `EmployeesList/Detail`, `Nomenclature*`, `XlsxAnalyzer.tsx` и любые новые экраны.
