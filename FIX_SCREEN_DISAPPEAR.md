# Что делать если экран пропадает после загрузки XLSX

## Проблема
- Загружаете XLSX файл
- Крутится колёсико ~5 секунд
- Экран приложения пропадает

## Что исправлено

### 1. Логирование на бэкенде
✅ Заменены `print()` на `logger.info()` и `logger.error()`  
✅ Добавлен `traceback` для ошибок  
✅ Включена буферизация вывода  

### 2. Защита на фронтенде
✅ Добавлена кнопка "Сырой JSON" для отладки  
✅ Добавлена обработка ошибок при рендере  
✅ Добавлена валидация данных перед сохранением  
✅ Показ сырого ответа в консоли браузера  

## Как отладить

### Шаг 1: Перезапустите контейнеры
```bash
docker compose down
docker compose up --build
```

### Шаг 2: Откройте логи бэкенда
В отдельном терминале:
```bash
docker compose logs -f backend
```

Теперь вы должны увидеть подробные логи:
```
2026-09-22 06:51:00,123 - __main__ - INFO - ======================================================================
2026-09-22 06:51:00,124 - __main__ - INFO - 📊 [XLSX ANALYZE] Начало анализа файла
2026-09-22 06:51:00,125 - __main__ - INFO - ======================================================================
2026-09-22 06:51:00,126 - __main__ - INFO - ✅ [XLSX ANALYZE] Получен файл: nomenclature.xlsx
2026-09-22 06:51:00,127 - __main__ - INFO - 💾 [XLSX ANALYZE] Файл сохранён: /tmp/tmp123.xlsx
2026-09-22 06:51:00,128 - __main__ - INFO - 🔍 [XLSX ANALYZE] Начинаем анализ файла...
```

### Шаг 3: Откройте консоль браузера
1. Нажмите F12
2. Перейдите на вкладку **Console**
3. Очистите консоль (кнопка 🚫)

### Шаг 4: Загрузите XLSX файл снова

Смотрите что появляется:

**В консоли браузера:**
```
📊 [FRONTEND] Начало анализа XLSX файла
📁 [FRONTEND] Выбран файл: nomenclature.xlsx
🚀 [FRONTEND] Отправляем запрос на бэкенд...
⏱️  [FRONTEND] Запрос выполнен за 10790мс
📥 [FRONTEND] Статус ответа: 200 OK
📊 [FRONTEND] Сырой ответ: {
  "file": "/tmp/tmp123.xlsx",
  "file_size_mb": 0.01,
  "sheets": [...]
}
```

### Шаг 5: Если экран пропадает

1. **Не закрывайте консоль браузера!**
2. Посмотрите есть ли ошибки в консоли (красным)
3. Нажмите кнопку **"Сырой JSON"** на странице
4. Если сырой JSON показывается — проблема в рендере
5. Скопируйте ошибку из консоли

## Кнопка "Сырой JSON"

Добавлена новая кнопка рядом с "Копировать для импортера":

```
[👁️ Нормальный вид]  [📋 Копировать для импортера]
```

Если нажать **"Сырой JSON"** — покажется сырой JSON ответ от бэкенда.

Это поможет понять:
- Приходят ли данные с бэкенда
- Какая структура данных
- Есть ли проблемы с данными

## Частые проблемы

### 1. Ошибка "Cannot read property 'X' of undefined"

**Причина:** В данных отсутствует обязательное поле

**Решение:**
- Нажмите "Сырой JSON"
- Посмотрите структуру данных
- Пришлите скриншот

### 2. Ошибка при рендере листа

**Причина:** Проблема в данных конкретного листа

**Решение:**
- В консоли будет ошибка с номером листа
- Переключитесь на "Сырой JSON"
- Найдите проблемный лист

### 3. Экран пустой, но нет ошибок

**Причина:** CSS проблема или данные пустые

**Решение:**
- Нажмите "Сырой JSON"
- Проверьте что `sheets` не пустой массив
- Обновите страницу (F5)

## Что прислать для отладки

Если проблема не решается, пришлите:

### 1. Логи бэкенда
```bash
docker compose logs backend | tail -100
```

### 2. Скриншот консоли браузера
- F12 → Console
- Загрузите файл
- Скриншот всех сообщений (особенно красных ошибок)

### 3. Скриншот "Сырой JSON"
- Нажмите кнопку "Сырой JSON"
- Скриншот содержимого

### 4. Информация о файле
- Размер файла
- Количество листов
- Пример содержимого (первые 3 строки)

## Быстрая проверка

```bash
# 1. Проверить что бэкенд работает
curl http://localhost:5000/health

# 2. Перезапустить всё
docker compose down
docker compose up --build

# 3. Открыть заново
# http://localhost:3000
```

## Если ничего не помогает

1. Полная очистка:
```bash
docker compose down -v
docker system prune -a
```

2. Пересборка:
```bash
docker compose up --build
```

3. Пришлите:
- Логи бэкенда (`docker compose logs backend`)
- Скриншот консоли браузера (F12 → Console)
- Скриншот "Сырой JSON"
